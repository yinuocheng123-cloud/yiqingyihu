# 版本记录：v0.13-快捷延期与物流批量解析

## 1. 本轮目标

本轮目标是在上一轮“负责人筛选与批量物流补录”基础上，继续压缩日常操作路径，重点解决两件事：

- 任务支持快捷延期
- 物流单号支持批量粘贴解析

本轮属于：

- 功能补充
- 使用效率提升
- 高频交互优化

## 2. 背景与上下文

本轮承接以下记录：

- `custom/notes/v0.12-负责人筛选与批量物流补录.md`
- `custom/notes/v0.11-任务安排与批量发货增强.md`

在 `v0.12` 之后，系统已经具备：

- 任务按负责人筛选
- 批量发货时逐单物流单号录入

但日常操作仍然还有两个明显可优化点：

第一，任务延期虽然已有能力，但仍然要打开弹窗手动改时间。  
对于真实使用来说，很多延期只是“顺延 1 天 / 3 天 / 7 天”，如果每次都开弹窗，会打断节奏。

第二，物流单号虽然能逐单录入，但仍然要逐行手输。  
实际业务里，经常是从物流系统整段复制单号列表，如果系统不能直接吃这段文本，批量发货的效率还是会被限制。

## 3. 问题分析

本轮的核心问题不是“能不能做”，而是“做得够不够顺手”。

任务延期的问题：

- 当前流程完整，但不够快
- 高频延期动作不应该总是走完整编辑流程

物流单号的问题：

- 当前流程已经支持逐单差异字段
- 但录入方式仍然偏手工
- 这意味着系统在结构上已经对了，但交互上还差一步

因此，本轮的重点就是把已经成型的能力继续压缩成更贴近日常节奏的动作。

## 4. 候选方案比较

### 方案一：保持当前流程不动

核心思路：

- 延期继续通过编辑弹窗完成
- 物流单号继续逐行手填

优点：

- 不需要继续改动
- 风险最低

缺点：

- 高频动作仍然会显得啰嗦
- 系统已经有批量能力，但还没有真正达到“顺手”

放弃原因：

这两个问题都是明显的交互优化点，而且修复成本低，不值得继续保留。

### 方案二：新增快捷延期按钮和物流单号粘贴解析

核心思路：

- 在任务操作列增加“延后 1 天 / 3 天 / 7 天”
- 在批量发货弹窗中增加粘贴区
- 支持按行粘贴：
  - `订单号 空格 物流单号`
  - 或仅粘贴物流单号
- 系统按当前选中顺序自动填充逐单物流单号

优点：

- 对当前使用场景帮助直接
- 不需要改数据库或新增后端接口
- 与现有结构兼容性高

缺点：

- 粘贴解析目前是轻量规则，不是复杂格式识别
- 若用户粘贴顺序和当前订单顺序不一致，仍需人工检查

最终选择原因：

这是当前最划算的增强方式，能立刻提升日常使用顺滑度。

## 5. 最终决策

本轮最终采用方案二，并做了以下关键决策：

1. 快捷延期先做三档：
   - 延后 1 天
   - 延后 3 天
   - 延后 7 天

2. 快捷延期基于当前到期时间顺延
   - 如果没有到期时间，则以当前时间为基准

3. 物流单号解析先做轻量版
   - 每行一个单号
   - 或每行“订单号 + 单号”
   - 解析时取每行最后一个字段作为单号

4. 仍保留原有逐单手工编辑入口，解析只是加速方式，不替代人工修正

## 6. 具体实现

本轮主要修改了以下文件：

- `apps/web/src/pages/tasks/TasksPage.tsx`
  - 新增“延后 1 天 / 3 天 / 7 天”快捷按钮
  - 直接调用现有任务编辑接口完成顺延

- `apps/web/src/pages/orders/OrdersPage.tsx`
  - 批量发货弹窗新增物流单号粘贴区
  - 新增“解析粘贴内容”按钮
  - 按当前订单顺序将粘贴内容映射到逐单物流单号输入区

## 7. 本轮优点

- 任务延期从“完整编辑动作”压缩成“单击动作”
- 批量发货录入速度进一步提升
- 新能力完全建立在现有结构之上，没有额外引入后端复杂度
- 系统更接近日常高频使用习惯

## 8. 本轮缺点与代价

当前方案仍然有清晰限制：

- 快捷延期目前是固定天数，不支持自定义快捷档位
- 物流单号粘贴解析依赖当前选中订单顺序
- 如果粘贴内容格式过于复杂，仍需要人工检查和修正
- 当前目录仍不是 Git 仓库，无法执行你要求的 `git pull`

这些限制在当前阶段是可接受的，因为本轮目标是把最高频交互先做到足够顺手。

## 10. 本轮结论

本轮最重要的结论是：

高频动作真正变顺手，靠的不是新增大能力，而是把已有能力压缩成更短路径。

另一个被证实的判断是：

物流单号批量解析不需要一开始就做复杂模板导入，轻量的按行解析已经能覆盖大部分个人使用场景。
