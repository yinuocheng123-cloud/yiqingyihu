# 版本记录：v0.15-首页负责人视角与任务优先级增强

## 1. 本轮目标

本轮目标是继续沿着“任务驱动工作台”的方向，把系统再往个人高频使用场景推进一层。

优先解决两件事：

- 首页缺少负责人视角摘要，登录后虽然能看到总待办，但还不能一眼看清“我今天先处理什么”
- 待办中心虽然已经支持筛选、延期和分配，但任务优先级仍然只能依赖自动规则，人工调整不够顺手

本轮属于：

- 功能补充
- 使用效率提升
- 可维护性增强

## 2. 背景与上下文

本轮承接以下记录：

- `custom/notes/v0.14-可测试数据与启动收尾.md`
- `custom/notes/v0.13-快捷延期与物流批量解析.md`

在 `v0.14` 之后，系统已经进入“直接 `npm run dev` 可测试”的状态，重点从“能否跑起来”切换到了“是否足够顺手”。

上一轮已经明确了两个下一步方向：

1. 首页补负责人视角摘要
2. 任务优先级快捷调整

本轮完全延续这个判断，没有新增大模块，也没有改动主链路模型。

## 3. 问题分析

表面现象有两个：

- 首页虽然有待办工作台，但更多是系统全局视角，不够像个人当天的工作台
- 任务优先级虽然存在，但人工处理过程中很难快速上调或下调

核心矛盾是：

- 当前系统已经能自动生成任务
- 但还缺“人工分拣任务”的轻量能力

如果没有负责人视角，首页更像统计页而不是操作页。
如果没有优先级快捷调整，任务中心更像列表而不是分发面板。

## 4. 候选方案比较

### 方案一：只补首页统计，不改任务编辑能力

核心思路：

- 首页增加“我的任务数”“我的紧急任务数”两个数字
- 不调整任务编辑接口

优点：

- 改动最小
- 风险最低

缺点：

- 只能看，不能顺手调整
- 无法真正把首页和待办中心联动成工作台

放弃原因：

收益不够，不能解决“任务分拣”这个核心问题。

### 方案二：首页补负责人摘要，任务编辑接口顺带支持优先级调整

核心思路：

- 首页新增“我的待办摘要”和“待领取任务”
- 后端任务更新接口扩展支持 `priority`
- 前端待办中心增加优先级快捷按钮和编辑项

优点：

- 使用收益直接
- 不需要新增表结构
- 与现有任务中心天然兼容

缺点：

- 任务更新接口职责略有扩展
- 首页逻辑会稍微复杂一些

最终选择原因：

这是当前阶段最划算的做法，既补观察视角，也补操作能力。

## 5. 最终决策

本轮最终采用方案二，并做了两个关键决策：

1. 优先级仍然保持轻量模型，只允许 `P1-P5`
2. 首页不做完整负责人看板，只做“我的待办摘要 + 待领取任务”两块核心视图

这样做的原因是：

- 先解决个人日常使用的判断成本
- 避免过早引入更重的统计模块

## 7. 本轮优点

相比上一轮，本轮的正向效果主要有：

- 首页更像个人工作台，而不是单纯总览页
- 待办中心首次具备了“人工分拣优先级”的能力
- 任务的自动生成和人工调整形成了更顺滑的配合
- 没有新增数据库表，也没有破坏已有业务链路

改善的质量属性包括：

- 可用性
- 可维护性
- 操作效率
- 可扩展性

## 8. 本轮缺点与代价

这一轮也有明确代价：

- 优先级调整目前只提供最常用的 `P1 / P2 / P3` 快捷入口，`P4 / P5` 仍然主要通过编辑弹窗设置
- 首页“待领取任务”目前只是未分配视角，还没有更细的来源分组
- 任务优先级仍然是人工和自动规则混合维护，后续可能需要更清晰的默认策略
- 当前目录依然不是 Git 仓库，无法执行你要求的 `git pull`

这些问题当前是可接受的，因为本轮目标是把工作台再推进一步，而不是把任务系统一次性做重。

## 10. 本轮结论

本轮最重要的结论是：

要把系统做得更像“个人操作台”，关键不只是继续加自动化，而是把“我的任务”和“优先级分拣”做得更顺手。

被证实的判断有两个：

- 首页负责人视角确实值得优先补
- 任务优先级不需要先做复杂规则引擎，先做轻量人工快捷调整就已经有明显价值

以后应默认继承的经验是：

- 任务中心的增强优先做高频动作压缩
- 首页优先承载“我今天要做什么”，而不是继续堆更多统计图

## 11. 下一轮建议

下一步最值得做的 1~3 件事：

1. 增加任务默认指派策略
   - 收益最高
   - 比如自动把客户类任务默认给负责人，把发货类任务默认给发货责任人

2. 增加任务优先级筛选和排序控制
   - 风险最低
   - 可以进一步提升待办中心的分拣效率

3. 增加消息提醒入口
   - 需要更多信息后再做
   - 适合后续和企业微信、短信或站内提醒结合
