# 版本记录：v0.7-内容素材与系统设置收口

## 1. 本轮目标

本轮目标是在已有客户、订单、回访、会员、伙伴、发货和看板基础上，补齐剩余两块核心后台模块：

- 内容素材管理
- 系统设置管理

本轮属于：
- 功能补充
- MVP 收口
- 可维护性提升

## 2. 背景与上下文

本轮承接：

- `custom/notes/v0.1-项目初始化与权限骨架.md`
- `custom/notes/v0.2-客户管理首轮落地.md`
- `custom/notes/v0.3-订单管理与客户详情闭环.md`
- `custom/notes/v0.4-回访复购与客户跟进沉淀.md`
- `custom/notes/v0.5-会员管理与首页待办可用化.md`
- `custom/notes/v0.6-发货履约与伙伴沉淀可用化.md`

前几轮已经把业务主链路跑顺，但后台仍少两个关键能力：

- 内容素材没有地方沉淀，客户原话与反馈仍然容易流失
- 系统口径配置和日志查看还没有统一入口

如果不补这两块，系统虽然能跑业务，但还不够“像一个完整可用后台”。

## 3. 问题分析

主要问题：

- 客户咨询、售后反馈、回访结论无法结构化沉淀为素材
- 来源渠道、客户类型、内容平台等基础口径无法在系统内维护
- 管理员缺少统一的日志查看入口

核心矛盾不是“要不要做很复杂的配置中心”，而是“如何在不扩张系统复杂度的前提下，把最实用的管理能力补齐”。

## 4. 候选方案比较

### 方案一：做完整配置中心和完整素材工作流

优点：
- 能力更完整

缺点：
- 明显超出当前 MVP 范围
- 会引入更多规则和复杂状态

放弃原因：
不符合当前阶段“能直接用”为先的目标。

### 方案二：先做最小实用版素材库和基础配置管理

核心思路：
- 素材库支持最核心字段录入和查询
- 设置模块先支持最常用配置类型
- 日志直接在设置页统一查看

优点：
- 改动集中
- 使用价值直接
- 不会把系统做重

缺点：
- 后续如果配置复杂度上升，仍需要更细的配置结构

选择原因：
最符合当前阶段 MVP 收口目标。

## 5. 最终决策

本轮采用“内容素材可录入 + 基础配置可维护 + 日志可查看”方案。

具体决策：

- 后端新增 `content-assets` 模块
- 后端新增 `settings` 模块
- 前端新增内容素材可操作页面
- 前端新增系统设置页面，包含配置项 Tabs 和日志表格
- 设置模块先聚焦四类配置：
  - `source_channel`
  - `customer_type`
  - `product_category`
  - `content_platform`

## 6. 具体实现

主要改动文件：

- 后端
  - `apps/server/src/modules/content-assets/`
  - `apps/server/src/modules/settings/`
  - `apps/server/src/common/enums/permission.enum.ts`
  - `apps/server/prisma/seed.ts`
  - `apps/server/src/app.module.ts`

- 前端
  - `apps/web/src/types/content-asset.ts`
  - `apps/web/src/types/setting.ts`
  - `apps/web/src/api/content-assets.ts`
  - `apps/web/src/api/settings.ts`
  - `apps/web/src/pages/content-assets/ContentAssetsPage.tsx`
  - `apps/web/src/pages/settings/SettingsPage.tsx`

实现效果：

- 可以新增内容素材
- 可以按编号、痛点、客户原话、标题钩子搜索素材
- 可以维护素材的来源类型、内容角度、平台、是否发布等信息
- 可以新增基础配置项
- 可以按配置类型查看配置项
- 可以在系统设置页查看操作日志

## 7. 本轮优点

- 素材沉淀链路真正落地
- 系统基础口径开始可维护
- 操作日志有了统一查看入口
- 到这一轮为止，后台的核心业务模块已经基本齐备

## 8. 本轮缺点与代价

- 内容素材目前还没有详情页和编辑页，只先做了新增和列表
- 系统设置还没有支持修改已有配置项的前端入口，后端已具备更新接口
- 日志目前以查询为主，还没有筛选与详情能力
- 前端包体继续增大，后续需要考虑路由拆分

## 9. 验证与结果

本轮已执行：

- `npm run lint -w apps/server`
- `npm run build -w apps/server`
- `npm run lint -w apps/web`
- `npm run build -w apps/web`

结果：

- 前后端类型检查通过
- 前后端构建通过
- 内容素材与系统设置功能已稳定接入现有 MVP

## 10. 本轮结论

到这一轮为止，这套“一清一护全球严选 OPC 操作系统”已经具备了 MVP 所需的核心后台能力：客户、订单、回访、会员、伙伴、发货、内容素材、首页看板、待办提醒、系统设置与日志查看都已有可操作入口。
