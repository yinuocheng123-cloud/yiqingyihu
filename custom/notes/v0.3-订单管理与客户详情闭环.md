# 版本记录：v0.3-订单管理与客户详情闭环

## 1. 本轮目标

本轮目标是在客户管理首轮落地的基础上，把“客户建档 -> 订单录入 -> 客户详情查看成交历史”这条主链路继续打通，具体包括：

- 实现订单管理模块最小 CRUD
- 创建订单时联动更新客户消费汇总
- 实现客户详情页
- 实现订单详情页

本轮属于：
- 功能补充
- 业务闭环推进

## 2. 背景与上下文

本轮承接以下记录：

- `custom/notes/v0.1-项目初始化与权限骨架.md`
- `custom/notes/v0.2-客户管理首轮落地.md`

上一轮已经完成客户列表和建档能力，但系统还停留在“客户有了，成交链路没接上”的状态。要真正推进业务，需要让客户与订单发生真实关联，并能在客户详情里看见购买结果。

## 3. 问题分析

当前核心问题不是订单功能做得不够复杂，而是客户与订单之间缺乏真实的业务连接。

主要矛盾：

- 客户录入后无法承接首次成交
- 客户详情看不到交易结果，不利于后续判断是否复购、是否可转会员
- 如果订单不回写客户汇总字段，客户模块的生命周期和消费数据会一直失真

## 4. 候选方案比较

### 方案一：一次性把订单、发货、物流、售后、回访全部做全

优点：
- 功能看起来更完整

缺点：
- 改动面过大
- 会明显拖慢第一条主链路落地
- 当前产品、发货、回访等依赖还未全部具备

放弃原因：
不符合最小可用和持续迭代原则。

### 方案二：先做订单最小闭环，并将结果回写客户

核心思路：
- 先实现订单列表、详情、新增、编辑
- 以客户关联、渠道、金额、收款状态、发货状态为第一批核心字段
- 同步刷新客户的首购、最近购买、累计购买次数、累计消费

优点：
- 能最直接提升业务可用性
- 让客户模块从线索库变成成交视图
- 为下一轮回访复购模块打基础

缺点：
- 订单商品明细、物流、售后仍是简化版

选择原因：
更符合当前主链路推进节奏。

## 5. 最终决策

本轮采用“订单最小闭环 + 客户详情视图”方案：

- 后端新增订单模块
- 订单创建和更新时联动刷新客户消费汇总
- 前端新增订单列表页、订单详情页和录单抽屉
- 前端新增客户详情页，展示基础资料、消费汇总、历史订单和回访摘要

关键取舍：

- 暂不强制要求订单商品明细
- 暂不接发货单、物流单号和售后记录编辑
- 暂不做复杂筛选、导出和批量操作

## 6. 具体实现

本轮主要改动：

- 后端
  - `apps/server/src/modules/orders/`
  - `apps/server/src/app.module.ts`

- 前端
  - `apps/web/src/types/order.ts`
  - `apps/web/src/api/orders.ts`
  - `apps/web/src/pages/orders/OrdersPage.tsx`
  - `apps/web/src/pages/orders/OrderDetailPage.tsx`
  - `apps/web/src/pages/customers/CustomerDetailPage.tsx`
  - `apps/web/src/router/index.tsx`

实现效果：

- 可以新增订单并绑定已有客户
- 订单列表能查看客户、渠道、金额、状态
- 客户列表可以进入客户详情
- 客户详情能看到历史订单和消费汇总
- 订单详情能回到客户详情

## 7. 本轮优点

- 第一条真实业务闭环进一步成立
- 客户模块和订单模块不再割裂
- 客户数据开始具备“线索 + 成交”双重视角
- 后续回访、复购、会员转化可以直接基于订单历史推进

## 8. 本轮缺点与代价

- 订单明细商品还没接产品模块
- 发货、签收、售后仍是基础状态字段，未形成完整履约子流程
- 客户详情中的回访区目前只是摘要展示，还不能录入
- 前端包体继续变大，后续需要按路由拆包优化

## 9. 验证与结果

本轮已执行：

- `npm run lint -w apps/server`
- `npm run build -w apps/server`
- `npm run lint -w apps/web`
- `npm run build -w apps/web`

结果：

- 前后端类型检查通过
- 前后端构建通过
- 新增订单模块和客户详情页未引入新的编译错误

## 10. 本轮结论

在当前阶段，订单模块最关键的价值不是“把订单做得很全”，而是把客户与成交连接起来，并把结果沉淀回客户视图。这个闭环一旦成立，后续回访复购和会员转化就有了稳定起点。

## 11. 下一轮建议

1. 实现回访复购模块，建立三次回访记录和预计复购时间
2. 在客户详情中补跟进记录与操作日志
3. 逐步接订单发货记录和物流信息，完善履约链路
