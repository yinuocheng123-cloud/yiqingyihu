# 版本记录：v0.9-任务驱动工作台首轮落地

## 1. 本轮目标

本轮目标是把系统从“模块式后台”推进到“任务驱动工作台”形态，让个人使用时不再需要自己逐页判断下一步，而是打开系统后直接围绕待办任务工作。

本轮属于：
- 功能补充
- 使用方式升级
- 自动化基础建设

## 2. 背景与上下文

本轮承接：

- `custom/notes/v0.8-上线前收尾与初始化可用化.md`

在上一轮之前，系统已经具备了主要业务模块，但使用方式仍然偏“管理系统”：

- 你需要先自己判断今天该处理什么
- 待发货、待回访、待转会员、待转伙伴这些动作分散在不同模块
- 缺少统一的任务收口视图

你提出的目标是更接近 OpenClaw 那类工作方式：打开系统后，尽量只做“打开、审核、发货、关闭”。

## 3. 问题分析

当前的核心矛盾不是“功能不够多”，而是“任务没有被系统结构化表达出来”。

主要问题：

- 新客户、新订单、待发货、待回访这些动作没有统一待办对象
- 系统虽然能记录状态，但不能自动告诉你下一步该做什么
- 首页更多是在展示统计，而不是驱动操作

## 4. 候选方案比较

### 方案一：继续在各模块里补提醒字段

优点：
- 改动相对小

缺点：
- 提醒仍然分散
- 你还是要自己决定下一步动作
- 不符合“工作台化”方向

放弃原因：
只能缓解问题，不能改变使用方式。

### 方案二：新增统一任务表和待办中心

核心思路：
- 用 `tasks` 表承接系统自动生成的待办
- 关键业务动作触发自动建任务
- 首页直接展示任务工作台

优点：
- 待办统一收口
- 能继续向自动化推进
- 最贴近你要的使用方式

缺点：
- 需要同步改动数据模型、后端服务和首页

选择原因：
这是当前最值得投入的方向。

## 5. 最终决策

本轮采用“任务表 + 自动建任务 + 首页待办工作台”方案。

首批任务类型：

- `LEAD_REVIEW`
- `ORDER_REVIEW`
- `SHIPMENT_PENDING`
- `FOLLOWUP_PENDING`
- `REPURCHASE_REVIEW`
- `MEMBER_REVIEW`
- `PARTNER_REVIEW`

任务状态：

- `OPEN`
- `IN_REVIEW`
- `DONE`
- `CANCELLED`

## 6. 具体实现

主要改动文件：

- 数据模型
  - `apps/server/prisma/schema.prisma`

- 后端
  - `apps/server/src/modules/tasks/`
  - `apps/server/src/modules/customers/customers.service.ts`
  - `apps/server/src/modules/orders/orders.service.ts`
  - `apps/server/src/modules/shipments/shipments.service.ts`
  - `apps/server/src/modules/followups/followups.service.ts`
  - `apps/server/src/modules/members/members.service.ts`
  - `apps/server/src/modules/partners/partners.service.ts`
  - `apps/server/src/common/enums/permission.enum.ts`
  - `apps/server/prisma/seed.ts`

- 前端
  - `apps/web/src/types/task.ts`
  - `apps/web/src/api/tasks.ts`
  - `apps/web/src/pages/dashboard/DashboardPage.tsx`

实现效果：

- 新客户会自动生成线索审核任务
- 新订单会自动生成订单审核任务和待发货任务
- 发货后会自动生成待回访任务
- 回访中标记复购/会员/伙伴机会后会自动生成对应审核任务
- 首页新增待办工作台，可直接：
  - 打开任务来源页面
  - 将任务标记为审核中
  - 将任务关闭

## 7. 本轮优点

- 首页开始真正承担“工作台”角色
- 系统开始从记录状态升级为分派动作
- 为后续进一步自动化打下了明确基础
- 更贴近个人日常使用场景

## 8. 本轮缺点与代价

- 当前任务规则仍是代码内置，不是可视化配置
- 首页已能审核和关闭任务，但还没有更细的批量处理能力
- 任务来源跳转仍然是基础版本，后续还可以更智能

## 9. 验证与结果

本轮已执行：

- `npm run prisma:generate -w apps/server`
- `npm run db:push -w apps/server`
- `npm run lint -w apps/server`
- `npm run build -w apps/server`
- `npm run lint -w apps/web`
- `npm run build -w apps/web`
- `npm run seed -w apps/server`

结果：

- 数据模型已同步到数据库
- Prisma Client 已更新
- 前后端类型检查和构建通过
- 新增任务权限已写入种子数据

## 10. 本轮结论

任务中心是这套系统从“可用后台”走向“高频操作台”的关键一步。到这一轮为止，系统已经开始具备你想要的那种使用方式雏形：不只是看数据，而是打开后直接处理待办。

## 11. 下一轮建议

1. 增加任务筛选与批量操作
2. 将任务规则配置化，减少后续写死逻辑
3. 接入外部 webhook 和定时任务，进一步向自动操作靠近
